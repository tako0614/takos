# はじめてのアプリ

このページでは、Takos Workspace にアプリを追加し、Apps から開くまでを説明します。Takos 自体をセルフホストする手順は [セルフホスト](/deploy/) にあります。

## 追加する前に

アプリの配布元から、次の情報を確認します。

- Git リポジトリの URL
- 利用する tag または commit
- OpenTofu モジュールがあるフォルダー
- 作成されるクラウドリソースと料金
- アプリが要求する権限

本番利用では、内容が後から変わる `main` や `latest` ではなく、tag または commit に固定します。

## 1. Apps を開く

対象の Workspace で Apps を開き、Git URL から追加する操作を選びます。

新しい Workspace にアプリは自動追加されません。必要なものだけを追加してください。

## 2. ソースを入力する

Git URL、tag または commit、モジュールのフォルダーを入力します。

Takosumi はリポジトリを読み取り、実行できる OpenTofu モジュールか確認します。リポジトリに表示用の情報がある場合は、アプリ名や候補を同じ画面に表示します。

## 3. 変更内容を確認する

実行前に、作成・更新・削除されるリソース、必要な入力、警告を確認します。

ここで表示される計画を承認するまで、実際のクラウド環境は変更されません。想定外の削除、権限、料金がある場合は進めないでください。

## 4. 完了を待つ

承認後、Takosumi が確認済みの計画を実行します。成功すると、起動 URL と公開された機能が記録されます。

Apps には次のいずれかが表示されます。

- **利用可能**: アプリを開ける
- **準備中**: デプロイがまだ完了していない
- **失敗**: 管理画面でエラーを確認する必要がある
- **起動 URL なし**: 画面を持たないツールやバックグラウンドサービス

## 5. Chat から使う

アプリがエージェント向けツールを公開している場合、Takos の Connections に表示されます。エージェントは必要になったときに `toolbox` からそのツールを探します。

```text
追加した文書アプリに、この Workspace のセットアップメモを作って。
```

アプリにツールがない場合でも、Apps から画面を開いて利用できます。

## 表示されないとき

1. Apps で対象アプリの状態を確認する
2. デプロイが完了しているか確認する
3. 起動 URL が出力されているか確認する
4. アプリの公開情報が現在の Workspace に許可されているか確認する
5. [トラブルシューティング](/deploy/troubleshooting) の「アプリが表示されない」を確認する
